# Style Guide

Below are a few tips when creating or editing pages:

# Content Arrangement

Material can be anywhere in difficulty, but should stay strictly within their subject areas and only require information that would normally precede it. For example, don't write a question involving dynamic memory allocation in the "Arrays Practice Problems" page, even if it relates to arrays, since DMA is a more complex topic. That question would be better placed with DMA. (Perhaps create a section on the page just for dynamically-allocated arrays in this case.)

# "Evergreen Content"

"Evergreen" refers to the idea that a page remains fresh and relevant ("green") forever. In other words, no matter how much time passes, the information contained within this project remains relevant. (Obviously, a project containing lots of information about the C language may itself become irrelevant if C is no longer used, but this is a separate issue.)

The goal with evergreen content is to write in a way that does not rely on any information that could go out-of-date.

- Writing about what is in the standard C99 standard? Great. That is a time-tested standard that isn't changing in the foreseeable future.
- *Linking* to the C99 standard in a separate page? This, while good information that probably won't age very quickly, will be contained on a page that will inevitably change or disappear one day. If there is relevant information on an external page, it should likely be within this project itself.
- What about a cool, interactive page that shows off some aspect of a concept? It may be worth adding to the main homepage of the published site (`src/index.md`) with the other additional resources. (This page, while technically not evergreen, at least centralizes all external links, making it less difficult to maintain.)
